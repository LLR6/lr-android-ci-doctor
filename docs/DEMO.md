# Android CI Doctor：可复现使用案例

作者：LLR6

## 要解决的场景

把 Android / Gradle / CI 日志整理成带源行号、上下文和排查建议的报告。适合 APK 构建、签名配置和产物上传失败时快速缩小排查范围。

## 复现

先克隆仓库并进入根目录，Python 3.10+。

```bash
python -m pip install -e .
android-ci-doctor examples/build.log --format json --context 1
```

这份[公开输出](../examples/showcase/output.json)由仓库源码实际运行产生，未手工修改。对应源码提交：`e453611881da6a981849a4eb0bc606d8e8073d88`。输入为仓库自带示例文本，没有使用用户真实日志。

## 结果怎么看

本次运行命中 **2 条规则**：`SIGN-01` 首次出现在 L3，`APK-01` 出现在 L4。报告先列签名线索，保留相邻上下文；这表示排查顺序，不是自动确认根因。

| 你的场景 | 可以先试什么 |
| --- | --- |
| 签名失败后又报 APK 不存在 | 先看首次命中的签名证据，再核查产物路径 |
| 想把日志分析接入流水线 | JSON 输出；命中时可返回退出码 2 |
| 需要给同事说明排查依据 | 附原行号和已去敏的上下文 |

## 换成自己的输入

用自己的构建日志替换 examples/build.log。先核对 first_line，再回到完整日志检查最早失败；未命中规则不代表构建成功。

## 有用的反馈

提交最小可复现输入、实际输出与预期行为。日志请先去敏；明确误报或遗漏发生在哪一行。详细能力边界和输入要求见 [README](../README.md)。
